# Retro App Family — Repository Guideline

Applies to: **RetroNotes**, **RetroCal**, **RetroReminder**, **RetroContacts**, **RetroFind** (and any future app in the family). A copy of this file lives in each repository at `docs/GUIDELINE.md`; the copies must stay identical.
Goal: every repository looks, reads and builds the same way, so a visitor who knows one knows all.

All repository documentation — README, changelog, guideline, screenshot alt texts, new code comments — is **English**.
(The apps themselves stay bilingual EN/DE where they already are.)

---

## 1. License

- **Code:** GNU General Public License v3.0 (GPL-3.0). The unmodified license text from <https://www.gnu.org/licenses/gpl-3.0.txt> lives in `LICENSE` at the repo root.
- Copyright line used in the README: `Copyright © 2026 Maik Klotz`.
- **App icon / artwork:** the app icon (`Resources/icon-source.png`, `AppIcon.icns`) is AI-generated and is **not** part of the GPL grant; all rights reserved by the author. Forks should ship their own icon. Textures generated by the repo's own scripts *are* covered by the GPL.
- **Trademarks / Apple:** every README carries the "not affiliated with Apple" disclaimer (section 3). No Apple images, fonts, sounds or textures are bundled.
- Distribution: GitHub only (source and notarized releases), not the App Store.

## 2. Repository layout

```
<repo>/
├── README.md              # structure in section 3
├── LICENSE                # GPL-3.0, verbatim
├── CHANGELOG.md           # Keep-a-Changelog style, newest first
├── Package.swift          # SwiftPM apps; RetroContacts builds with swiftc and has none
├── build.sh               # dev build  → build/<App>.app (always under build/)
├── release.sh             # Developer ID + hardened runtime + notarize → release artifact
├── Sources/  Tests/  Resources/
├── Reference/             # measuring / comparison / asset tooling (python)
├── docs/
│   ├── GUIDELINE.md       # this file
│   ├── COMPLIANCE.md      # optional: Apple compliance / legal notes (English)
│   └── screenshots/       # README images only, see section 4
└── .gitignore             # .build/ build/ .swiftpm/ *.xcodeproj *.dmg *.zip .DS_Store Reference/out/
```

Rules:
- Exactly two entry scripts: `build.sh` and `release.sh`. No `package.sh`, `make.sh`, …
- Tooling scripts go in `Reference/` (not `tools/`).
- Screenshot generation script (if any) is `docs/make-screenshots.sh`.
- Repo name = app name in CamelCase: `RetroNotes`, `RetroCal`, `RetroReminder`.

## 3. README structure

Use these sections **in this order, with these exact headings**. Omit an optional section rather than leave it empty.

| # | Heading | Required | Content |
|---|---|---|---|
| 0 | `# <AppName>` | yes | Title. |
| 1 | tagline | yes | One paragraph, max. 3 sentences: *what it is* (native macOS app), *the look it recreates* (OS X 10.8 Mountain Lion, skeuomorphic: leather, paper, glass), *what makes it real* (no mock-up; what data it works with). |
| 2 | hero image | yes | `docs/screenshots/hero.png`, centered, `width="820"`. |
| 3 | badge/tech line | yes | Blockquote: `Swift 5.9 · AppKit + SwiftUI · macOS 14+ · Apple Silicon and Intel · English and German · GPL-3.0` (adjust to facts), followed by the Apple disclaimer in the same blockquote. |
| 4 | `## Features` | yes | Bullet list, **bold lead-in** + dash + one line each. 6–10 bullets, most important first. Always ends with *Privacy* (what is stored, where, no network) and, if present, *Accessibility* bullets. |
| 5 | `## Screenshots` | yes | Gallery per section 4. Closing italic line: *All images show invented demo data.* |
| 6 | `## Installation` | yes | Download the notarized DMG/ZIP from [Releases](../../releases), drag to *Applications*, system requirement, first-launch permission dialogs. |
| 7 | `## Build from source` | yes | Fenced `bash` block with `./build.sh`, `./release.sh`, test command; 1–3 sentences on signing/notarization prerequisites. |
| 8 | `## Keyboard shortcuts` | optional | Table `Key \| Action`. |
| 9 | `## Accessibility` | optional | VoiceOver and keyboard coverage; link to checklist file if one exists. |
| 10 | `## Testing` | yes | Self-tests, unit tests, pixel-comparison tooling; honest statement of how close the look is to the original. |
| 11 | `## Project layout` | optional | Table `File \| Purpose` for the main source files and `Reference/`. |
| 12 | `## Data & privacy` | yes | Where data lives (path), what is read from the system (EventKit, Automation…), "no network access". |
| 13 | `## Limitations` | yes | Honest bullet list: measured vs. assumed values, unsupported features, known gaps. |
| 14 | `## License & legal` | yes | Fixed block, see below. |

### Style rules
- Present tense, active voice, no marketing adjectives. Say what it does.
- Feature bullets: `- **Name** – description.` (en dash, trailing period).
- Use real UI names in *italics* (*File › Back up all notes…*), key combos with symbols (⌘N).
- Shell commands in fenced `bash` blocks, one purpose per line with a `#` comment.
- Relative links only (`LICENSE`, `../../releases`, `docs/screenshots/…`).
- Limits and unverified claims go under *Limitations*, never into Features.
- Length target: 80–200 lines.

## 4. Screenshots

- **Location:** `docs/screenshots/`. Nothing else lives there.
- **Naming:** lowercase English kebab-case, no language suffix: `hero.png`, `day.png`, `month.png`, `search.png`, `settings.png`, `popover.png`, `single-note.png` …
- **Language:** English UI (`-AppleLanguages "(en)" -AppleLocale en_US`). A German variant is allowed only as an extra, named `german-ui.png`.
- **Content:** demo data only (`-demo` flag or demo store), invented, no real names, mails or places. Never screenshot a user's own data.
- **Format:** PNG, window-only capture, rounded corners and soft shadow on transparent background (see RetroReminder's `docs/process-screenshots.py`), Retina (2×) where the app supports `-scale=2`. Keep each file < 1 MB (`optimize=True`).
- **Required set:**
  1. `hero.png` — main window in its signature state; used at the top of the README.
  2. 3–8 more images covering the main views and one detail (popover/dialog), one settings window.
- **Gallery layout:** HTML table, two columns, caption row under each image row; narrow images (compact mode, popovers) get an explicit `width`. Every `<img>` has a meaningful `alt` text.
- **Reproducible:** if the app has a snapshot flag, `docs/make-screenshots.sh` regenerates every image; README mentions it in one line.

## 5. Features list — what to cover

Write each app's list from this checklist; mention only what exists:

1. Core views / objects (what the user manipulates)
2. Creating and editing flow (incl. natural-language input if present)
3. System integration (EventKit, Notes via Automation, …) and what is read/written
4. Search
5. Import / export / backup formats
6. Multi-window / compact / full-screen behaviour
7. Customization: **custom app icon** (PNG 256 × 256 where implemented), language, time format
8. Keyboard and VoiceOver support
9. Privacy: local only, no network, permissions requested lazily

## 6. Changelog

`CHANGELOG.md`, newest first, one `## <version> – <YYYY-MM-DD>` heading per release with bullet points grouped by *Added / Changed / Fixed* when more than three entries. The version matches `CFBundleShortVersionString` and the Git tag (`v1.2`) and the GitHub Release title (`<AppName> 1.2`).

## 7. Releases

- Release assets: `<AppName>-<version>.dmg` (signed with Developer ID, hardened runtime, notarized, stapled). No `.zip`-only releases.
- Release notes = the matching changelog section.
- Release flow is always `./release.sh`; the notary profile name is configurable via `NOTARY_PROFILE` (default `Retromac`).

## 8. Checklist before pushing

- [ ] `LICENSE` is GPL-3.0 and README license section matches
- [ ] README follows section 3 (headings, order), English only
- [ ] `docs/screenshots/hero.png` exists, English UI, demo data
- [ ] `CHANGELOG.md` has the current version
- [ ] `.gitignore` matches the template
- [ ] `./build.sh` and the test command from the README work on a clean clone
- [ ] No Apple assets, no personal data, no signing secrets in the tree
